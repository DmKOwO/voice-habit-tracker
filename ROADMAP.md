до exit code 0, отмечать `[x]`. Когда `[ ]` не остаётся — профилирование + новые 10 задач.

## Фаза B — Аудио-движок: ядро реального времени (10 ключевых фич)

Формат ядра: PCM16, mono, 16 kHz (STT-ориентирован), с возможностью конвертации.

- [x] **B1. AudioFormat + AudioFrame.** Единый формат кадра, конвертация
  sample rate/каналов/битности, валидация, без платформенных зависимостей.
- [x] **B2. Lock-free Ring Buffer (SPSC).** Power-of-two, кольцевые индексы, memory
  barriers без блокировок, счётчики over/underrun, тест на гонки и xrun.
- [ ] **B3. Пре-буферизация (look-back).** Запись начинается с кольца «хвоста» предыдущих
  N мс, чтобы не терять начало фразы после нажатия.
- [ ] **B4. Адаптивный jitter-буфер.** Поддержание целевой глубины, компенсация дрейфа
  часов, деградация без артефактов при переполнении.
- [x] **B5. DSP-цепочка (plugin graph).** `AudioProcessor` интерфейс, граф с
  включением/отключением и bypass, измерение времени каждого узла.
- [x] **B6. Anti-clicking / de-clicker.** Подавление транзиентов на стыках, без
  «щелчков» при остановке/паузе.
- [x] **B7. Адаптивный шумовой гейт.** Оценка noise floor, мягкое открытие/закрытие,
  anti-chatter.
- [x] **B8. DC-offset + high-pass.** Удаление постоянной составляющей и гула сети.
- [x] **B9. RMS-метр, пик, детект клиппинга.** Реальные уровни вместо декоративной
  «волны» в UI, замеры в dBFS.
- [ ] **B10. LUFS-подобная нормализация.** K-weighting (近似), гейтинг, нормализация к
  целевому уровню, защита от перегрузки.
- [x] **B11. FFT-анализатор.** Radix-2 БПФ, окно Ханна, спектр, доминирующая частота,
  спектральный центроид, полосы шума.
- [ ] **B12. Ресемплинг.** Линейный + полифазный для качества, 44.1/48 кГц → 16 кГц.
- [ ] **B13. Горячая смена аудиоустройств.** `AudioDeviceMonitor` на Android
  (`AudioDeviceCallback`), реакция на route change: пауза, переоткрытие, продолжение
  без потери буфера.
- [ ] **B14. Детектор xruns + замер задержки.** Over/underrun, сквозная задержка,
  p50/p95, отчёт в stdout и в журнал операций.
- [ ] **B15. Профилировщик аудио-пайплайна.** CPU/аллокации на узел, throughput,
  детект «горячих» мест, вывод в терминал.
- [ ] **B16. Headless CLI.** JVM `main`: прогон WAV через пайплайн, статистика,
  JSON-вывод, прогон audio-diff наборa — используется в CI и в тестах.
- [x] **B17. WAV I/O.** Чтение/запись PCM16 WAV, генерация фикстур (тишина, тон, клик).
- [ ] **B18. Хранилище аудиофайлов.** Retention-политика, лимит размера кэша,
  очистка по возрасту, защита от утечки диска.

### Прогресс фазы B
- B1 `core/audio/engine/AudioFormat.kt`: value-класс формата, downmix без потери 3 дБ,
  interleave/deinterleave, линейный ресемплинг, нормализация пика. Тесты: 11.
- B2 `SpscAudioBuffer.kt`: lock-free SPSC на атомарных индексах, степень двойки,
  две политики переполнения, раздельные метрики `droppedSamples` / `rejectedSamples`
  (потеря ≠ back-pressure), пиковая заполненность. Стресс-тест: 500 000 сэмплов
  через 2 потока за 12 мс, порядок соблюдён, потерь 0.
- B5-B9 `AudioProcessor.kt` + `DspNodes.kt`: граф с замером времени на узел,
  DC-offset, high-pass 80 Гц, de-clicker (счётчик щелчков), адаптивный гейт,
  RMS/пик/клиппинг, сглаживание уровня. Тесты: 14.

- B11 `FftAnalyzer.kt`: radix-2 БПФ, окна RECT/HANN/HAMMING/BLACKMAN, пик с суббинной
  параболической интерполяцией, спектральный центроид, энергия полос, `Spectrum` без аллокаций
  в `analyze`. **Найден реальный баг**: `peakIndex()` искал максимум до `size/2`, из-за чего
  тон выше 4 кГц (бин 384 при N=1024/16 кГц) «не находился» вовсе. Пойман сверкой с прямым
  DFT, а не «на глаз».
- B17 `WavIo.kt`: запись/чтение PCM16 WAV, `AudioDiff` (метрики отклонения вместо побайтового
  сравнения — ИIR-фильтры всегда сдвигают фазу), `AudioFixtures` (тон, тишина, шум, щелчок,
  свип, гул+шум).
- D1/D2: FFT-тесты (440 Гц: пик ±2 Гц после интерполяции, амплитуда, утечка, слик-окна),
  стресс-тест кольца 500 000 сэмплов / 12 мс / 0 потерь, тест политики DROP_OLDEST.
- Всего тестов в проекте: 139 (было 67).

### Проверено на эмуляторе (muse_visual, Android 14)

Все четыре режима, переопределение режима, правка темы конспекта, выбрасывание секций,
создание задачи из конспекта, закрепление и удаление, пустое состояние, бэкап с
последующим импортом (2 конспекта и 7 задач восстановлены полностью), узкий экран

* Миграция 6→7 на живых данных: `user_version` 6 → 7, таблица и оба индекса созданы,
  все 18 колонок на месте, запись читается. Инструментальные тесты: 3 из 3 зелёных.

Найдено и исправлено в чужом коде по ходу:

- Кнопки шторки разбора уезжали за нижний край экрана на длинном разборе: `ModalBottomSheet`
  меряет содержимое по `wrapContent`, и `weight(1f)`/`fillMaxHeight` там не работают.
  Кнопки перенесены последним элементом скролл-списка.
- Блок команд (удалить/перенести/фокус) был вложен в `if (tasksState.isNotEmpty())`:
  команда «удали задачу X» вообще не показывалась, если новых задач не было.
- FAB перекрывал транскрипт в читалке конспекта: 32dp отступа снизу вместо 132dp.
- Кнопка «Назад» в онбординге переносилась по буквам («Наза / д»): стандартные 24dp
  горизонтальных отступов съедали ширину слова.
- Список последних страниц онбординга был вписан вручную (`coerceIn(0, 2)` и `page < 2`
  в двух местах) — добавление страницы молча ломало последнюю кнопку.
- `Regex("[—–-:,.\s]")` в разборе конспекта ронял разбор на любой фразе: дефис без
  экрана внутри класса символов компилируется как диапазон от тире до двоеточия.

Ограничения проверки: облачный путь (Groq + Gemini) проверен по коду и контракту JSON,
без живых ключей; живая запись с микрофона на эмуляторе не проверялась — разбор
проверялся через «Поделиться текстом», который идёт ровно в тот же конвейер.
