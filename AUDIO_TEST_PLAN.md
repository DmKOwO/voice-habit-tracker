# Как тестировать аудио в voice-habit-tracker

Проблема: `MediaRecorder` и `SpeechRecognizer` — Android-классы, их нельзя создать в JVM-тесте.
Поэтому аудио-конвейер делится на 4 слоя, и каждый тестируется своим инструментом.

## Слой 0. Чистая логика (JVM, `app/src/test`, мгновенно)
Никаких Android-классов — только `java.io`/`java.time`.

1. **Анализатор сигнала** `core/audio/AudioLevelAnalyzer` (чистая Kotlin):
   RMS и пик по PCM-буферу, детектор тишины, детектор обрезки (файл короче minDuration),
   расчёт длительности по заголовку WAV. Тесты: синтезируем WAV in-memory
   (`TestAudioFactory.silence(16000)`, `.tone(freq, ms)`, `.click()`), проверяем
   `rms > 0` для тона, `rms ≈ 0` для тишины, порог детекции, корректный разбор заголовка.
2. **Нормализация транскрипта** `core/audio/TranscriptNormalizer`:
   trim, схлопывание пробелов, снятие пунктуации, нормализация «ё/е», приведение
   числительных («в 18 тридцать» → «18:30»). Property-тест на 2000 сгенерированных
   строках: идемпотентность `normalize(normalize(x)) == normalize(x)` и непустота
   результата при непустом входе.
3. **Золотой корпус фраз** `app/src/test/resources/transcripts.tsv`
   (`фраза \t ожидаемое_действие \t ожидаемый_тип \t ожидаемая_дата`) — десятки строк
   реальных фраз пользователя, включая баги из issue («надо купить витамины»,
   «завтра надо поучить английский»). Один параметризованный тест гоняет весь корпус
   через `OfflineVoiceParser` — регрессия по разбору ловится сразу.
4. **Контракты с заглушками**: `FakeAudioRecorder`, `FakeSpeechRecognizerEngine`
   (сценарии: partial→final, `ERROR_NO_MATCH`, `ERROR_SPEECH_TIMEOUT`, недоступен сервис,
   пустая запись). Через них тестируется `HomeViewModel`: гонка `stopListening()`/финальный
   результат, баннер «офлайн-режим», сообщение об ошибке записи, отмена записи.

## Слой 1. Сетевой путь (JVM + MockWebServer)
`DirectAiService.transcribeAudioGroq` / `parseIntentGemini` тестируются против
`okhttp3.mockwebserver`: заранее заданные ответы Groq/Gemini + офлайн-фолбэк при 401/500.
Проверяется: передаётся ли реальный файл, парсится ли контракт, не утекает ли ключ в лог,
какой фолбэк выбран. Замер латентности — через инъецируемый `Clock`, без `sleep`.

## Слой 2. Реальная БД и миграции (`app/src/androidTest`)
- `HabitToggleRealRoomTest`: реальный Room (in-memory), toggle привычки → **логи не исчезают**.
  Это главный регрессионный тест на `INSERT OR REPLACE` + `ON DELETE CASCADE`.
- `MigrationTestHelperTest` (нужен `exportSchema = true`): проверка каждой миграции,
  что данные и история переживают апгрейд версии.
- Миграция аудио-очереди: запись `PENDING_UPLOAD` → после обработки `APPLIED`.

## Слой 3. Реальный микрофон и распознавание (`androidTest`, только на устройстве/эмуляторе)
- `MediaRecorder` round-trip: записать 1–2 с, проверить `MediaMetadataRetriever`
  (длительность > 0, sample rate 16000, моно), воспроизводимость через `MediaPlayer`.
- Реальный `SpeechRecognizer` — только smoke-тест «сервис доступен / недоступен»;
  качество распознавания не тестируется кодом.
- Скрипт `scripts/record-fixtures.sh`: снимает фикстуры с реального устройства
  (`adb shell screenrecord`-подобный сценарий через QuickRecordActivity), складывает в
  `app/src/androidTest/assets/audio/`. Фикстуры используются в goldens-тестах STT.

## Метрики, которые стоит измерять
- `sttDurationMs`, `llmDurationMs` уже пишутся в `voice_logs` — добавить сводку
  (p50/p95) на экране истории, чтобы регрессия скорости была видна.
- Доля записей, которые не распознались (`status = FAILED`) — индикатор качества STT.
- Размер `cacheDir` (аудио-утечки) — проверяется тестом на очистку старых файлов.

## Чего тестами НЕ покрыть
- Качество распознавания речи и шумоподавление — только вручную/на реальном устройстве.
- Поведение конкретного OEM `SpeechRecognizer` — только smoke.
- Сетевые ответы реальных сервисов — фиксируются как fixture-JSON, а не ломают сборку.
