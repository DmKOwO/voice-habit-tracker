# Подпись релизов: текущее состояние и ротация

## Что фактически происходит

Проверено по опубликованным APK и по секретам репозитория.

**Релизы подписываются стоковым debug-keystore Android SDK.**

```
$ apksigner verify --print-certs voice-habit-tracker-v1.1.0.apk
Signer #1 certificate DN: C=US, O=Android, CN=Android Debug
Signer #1 certificate SHA-256 digest: 45f8c474...37da1

$ keytool -list -v -keystore ~/.config/.android/debug.keystore -storepass android
Alias name: androiddebugkey
SHA256: 45:F8:C4:74:0C:56:41:3B:07:B2:5E:A1:4D:B4:70:BE:27:...
```

Это тот же ключ, что лежит в секрете `KEYSTORE_BASE64`. Он поставляется с
каждым Android SDK, его пароль — слово `android`, и он есть у каждого, кто
когда-либо ставил Android Studio.

**Ключ `release.jks` из репозитория не подписал ни одного релиза.**
У него другой отпечаток (`0D:04:27:F2:2C:75:...`) и другой алиас (`dairy`).
Он использовался только для локальных сборок на этой машине. Именно поэтому
в README проекта сказано «постоянный ключ, чтобы подписи всегда совпадали» —
совпадали они только внутри локальной сборки, а не между CI и телефоном.

## Чем это плохо

Приложение само скачивает APK из GitHub Releases и предлагает его установку.
Если релиз подписан ключом, который есть у каждого в мире, то:

1. Кто угодно клонирует репозиторий и собирает APK, подписанный тем же ключом.
2. Публикует его как релиз.
3. Приложение скачивает его, видит валидную подпись и предлагает обновление.

Подпись совпадает, потому что она дефолтная. Это относится ко всем
выпущенным версиям, v1.0.1 … v1.2.6.

Оценка риска именно для этого проекта невелика: он делается для себя,
репозиторий под твоим единственным контролем, и подпись не даёт
возможности обойти разрешения внутри приложения. Но это блокер для
публичного релиза: приложение в Google Play нельзя публиковать с ключом,
который общеизвестен.

## Что уже исправлено в коде

- Keystore и `keystore.properties` исключены из git (`.gitignore`).
- Пароль подписи **не имеет фолбэка** в `build.gradle.kts`: сборка падает
  с понятной ошибкой, если параметры не заданы.
- `release.yml` берёт ключ **только** из секрета `KEYSTORE_BASE64`, а не из
  файла в репозитории.
- В CI добавлены гейты: `testDebugUnitTest` и `lintDebug` перед сборкой.

Ключи ИИ (Groq/Gemini) в сборку больше не попадают — `bundledKey()` молчит
по умолчанию. Они работали на бесплатных тарифах и не являются секретом,
но в APK им не место: там они достаются через `strings`.

## Ротация (нужно сделать один раз)

### 1. Сгенерировать настоящий ключ

```bash
mkdir -p ~/keys
keytool -genkeypair -v \
  -keystore ~/keys/dairy-release.jks \
  -alias dairy \
  -keyalg RSA -keysize 4096 -validity 10000
```

### 2. Записать параметры локально

```bash
cp android/app/keystore/keystore.properties.example \
   android/app/keystore/keystore.properties
```

Заполнить `storeFile`, `storePassword`, `keyAlias`, `keyPassword`.
Файл не коммитится.

### 3. Сохранить в GitHub Secrets

```bash
base64 -w0 ~/keys/dairy-release.jks    # → KEYSTORE_BASE64
```

Пароль и алиас — в `KEYSTORE_PASSWORD` / `KEY_ALIAS` / `KEY_PASSWORD`.

### 4. Что произойдёт с установленным приложением

Android отклонит обновление с другим сертификатом:

```
INSTALL_FAILED_UPDATE_INCOMPATIBLE
```

Приложение покажет ошибку установки. Обойти это нельзя — это защита Android,
и она работает как задумано.

**Значит установку придётся сделать один раз вручную:** удалить dairy и
поставить APK с новой подписью. Данные при этом теряются, поэтому перед
удалением сохрани бэкап: «Настройки → Резервная копия» экспортирует всё в
JSON. После переустановки импортируешь его обратно.

Так как проект пока личный, цена этой операции — одна ручная переустановка.
После неё подпись настоящая, и версию можно публиковать публично.

### 5. Очистить историю репозитория (по желанию)

`release.jks` остаётся в коммитах. Убрать:

```bash
# ⚠️ Перезапись истории. Сделайте, когда готовы снести все локальные копии.
git filter-repo --path android/app/keystore/release.jks --invert-paths
git push --force --tags origin main
```

Для безопасности это уже не обязательно: ключ, который там лежит, не
подписывал ни одного релиза. Но оставить его в истории — плохая практика.
