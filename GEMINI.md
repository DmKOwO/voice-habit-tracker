# Voice Habit & Task Tracker — Инструкции и правила проекта

## 🚨 КРИТИЧЕСКОЕ ПРАВИЛО: ОБЯЗАТЕЛЬНЫЙ OTA-РЕЛИЗ (MANDATORY OTA POLICY)

### ⚠️ ПРАВИЛО №1: ВСЕГДА ВЫПУСКАТЬ OTA-РЕЛИЗ ПОСЛЕ ЛЮБЫХ ИЗМЕНЕНИЙ
**НЕЗАВИСИМО ОТ ТОГО, ПРОСИЛ ЛИ ПОЛЬЗОВАТЕЛЬ ЯВНО ВЫПУСТИТЬ OTA ИЛИ НЕТ:**

Каждый раз, когда завершается любая задача, багфикс, исправление UI/UX, рефакторинг или добавление новой функциональности:
1. **Прогон тестов:** Убедиться, что unit-тесты проходят:
   ```bash
   cd android && ./gradlew testDebugUnitTest
   ```
2. **Инкремент версии и запуск релиза:**
   - Выполнить скрипт релиза из корня проекта:
     ```bash
     ./release.sh
     ```
     (или с явным указанием версии: `./release.sh X.Y.Z`).
   - Скрипт автоматически обновляет `android/version.properties` (`VERSION_NAME` и `VERSION_CODE`), фиксирует изменения в git, создаёт тег `vX.Y.Z` и пушит ветку и теги в GitHub (`origin main --tags`).
3. **Контроль публикации OTA:**
   - После пуша тега GitHub Actions автоматически запускает workflow `.github/workflows/release.yml`, компилирует релизный APK и публикует релиз на GitHub Releases (`DmKOwO/voice-habit-tracker`).
   - Проверить запуск через GitHub CLI:
     ```bash
     gh run list --limit 1
     ```
4. **Информирование пользователя:**
   - В итоговом ответе ВСЕГДА указывать номер новой версии OTA (например, `v1.1.1`), ссылку на релиз на GitHub и подтверждать, что обновление готово к установке по воздуху.

> [!IMPORTANT]
> **Это правило действует ВСЕГДА и БЕЗ ИСКЛЮЧЕНИЙ.** Любая задача считается полностью завершённой ТОЛЬКО тогда, когда код протестирован, закоммичен, создан новый тег версии и запущен OTA-релиз.

## 🎨 Стандарты дизайна (Duro Design System)
- **Цветовая палитра:** Фон `#0C0C12`, Карточки `#161622`, Границы `#242436`, Акцент ритма `#FF6B35` (DuroOrange), Дневник `#8B5CF6` (DuroJournalLavender), Текст `#FFFFFF` / `#8A8A9E`.
- **Эргономика тапов:** Минимальный размер кликабельных областей (Touch Target) — **44–48 dp** по стандарту Android Accessibility.
- **Нижняя навигация (`DuroBottomNavigation`):** Никаких мёртвых зон! Все вкладки делят ширину бара равномерно (`Modifier.weight(1f).fillMaxHeight()`).
- **Свайпы и списки:** Запрещено использовать полноэкранный `HorizontalPager`, если внутри есть горизонтально скроллящиеся ряды чипов (`LazyRow`), во избежание перехвата кликов микро-жестами.

## 🏛️ Архитектурные принципы
- **Local-First:** Данные всегда хранятся локально (Room DB + Obsidian Vault через Android Storage Access Framework).
- **Offline First:** Приложение должно полноценно функционировать локально даже при отсутствии сети или API-ключей.
