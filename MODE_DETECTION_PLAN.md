# H1 — «Просто скажи» (план и разбор реализации)

> Задача: сделать так, чтобы приложение **само** определяло — человек ставит задачу
> или просто говорит. И дать ему настоящий диктофон с выжимкой разговора, а не
> заметку, которая исчезает.

---

## 1. Что было не так

Разбор фразы начинался с попытки вытащить из неё задачу. Любой поток мыслей без
маркеров «надо / напомни / завтра» падал в `quickNotes` — список, который:

* **никогда не сохранялся** (в `ApplyVoiceActionsUseCase` нет ни одной строки про `quickNotes`);
* **никогда не показывался** в шторке разбора;
* **не отображался ни на одном экране**.

То есть фраза «я тут размышляю про отпуск» или «мы тут обсуждали релиз» заканчивалась
пустой шторкой и тихим авто-сохранением, которое ничего не сохраняло. Человек наговорил
пять минут — и потерял всё.

Одновременно с этим режим «просто поговорить» был невозможен в принципе: не из
интерфейса, а из модели данных.

## 2. Решение в одном абзаце

Разбор перестроен: **сначала определяется намерение, потом извлекаются сущности.**

```
фраза ──► IntentRouter ──► режим ──┬─ LOG     → сущности из глагола действия
                                   ├─ MIXED   → сущности из «что дальше» + конспект
                                   ├─ DICTATE → конспект, список дел не трогаем
                                   └─ QUERY   → сводка дня / конспект-вопрос
```

Режим — это не подпись, а контракт разбора: он решает, какие таблицы вообще будут
записаны. Пользователь может переопределить режим в шторке, и переопределение
**пересобирает** разбор, а не перерисовывает ярлык.

## 3. Ключевые решения и почему именно такие

### 3.1 При неопределённости побеждает `DICTATE`, а не `LOG`

| Ошибка | Последствие | Обратима? |
|---|---|---|
| Выдумать задачу из обрывочной фразы | мусор в списке дел, сорванный стрик привычек | нет |
| Не заметить задачу внутри монолога | действие лежит в разделе «что дальше» конспекта | да, один тап |

Ошибка первого рода бьёт по данным, второй — только по удобству. Поэтому
`IntentRouter` при равенстве сигналов выбирает поток мыслей.

### 3.2 Детектор режима работает без сети

`IntentRouter` — чистая функция от строки: ни моделей, ни ключей, ни сети.
Фича, ради которой человек говорит «просто запиши», не должна ломаться там, где
нет интернета, и падать ровно на длинном потоке мыслей — самом сложном случае для
таймаута. Слой сети может уточнить вердикт, но не является условием его работы.

### 3.3 Задача в режиме `MIXED` строится из раздела «что дальше», а не из сырой речи

Первая версия брала название из `extractActions(всё_что_сказал)`. На реальном монологе
это давало задачу **«Короче тут надиктовываю мысли после разговора с»** — первые шесть
слов потока, попавшие в список дел. Теперь действие вытаскивается из законченных
фраз-«шагов», а дата берётся из **этой же** фразы: фраза «переносим релиз на пятницу,
… и надо бы предупредить команду» не ставит «предупредить команду» на пятницу.

### 3.4 Конспект пишется сразу, а не по кнопке «Применить»

Диктофон не должен спрашивать разрешения на сохранение. Если пользователь закрыл
шторку, разговор потерян навсегда — ровно тот случай, ради которого он его записывал.
Поэтому `persistDigest` вызывается на разборе, а `applyVoiceAction` дописывает
финальные правки (тема, убранные секции, исправленный режим).

### 3.5 Каждая секция конспекта заполняется только если она есть

Пустой «открытые вопросы» честнее выдуманного пункта: выдуманный вопрос читается
как реальный и всплывает через неделю в виде «а что это было?».

### 3.6 Время 14:00 показывается, хотя его не было в речи

14:00 — время по умолчанию во всём приложении (редактор задачи ставит то же самое),
и именно оно будет сохранено. Скрывать его в шторке значило бы показать «до завтра»,
а потом обнаружить в списке дел «14:00 · 28 SEP»: расхождение заметил бы уже
пользователь, и уже не мог бы снять галочку.

### 3.7 Кнопки шторки лежат в скролл-списке, а не под ним

`ModalBottomSheet` меряет содержимое по `wrapContent`, и блок «как я это понял»
выдавливал кнопки за нижний край экрана — на длинном разборе сохранить запись было
нечем. Проверено на эмуляторе: `fillMaxHeight(0.86f)` и `weight(1f)` здесь не
срабатывают, помогает только перенос кнопок последним элементом списка.

## 4. Что получилось

| Было | Стало |
|---|---|
| «Просто поговорить» → пустая шторка, слова теряются | 4 режима, определяются сами, видны с уверенностью и причиной |
| Заметка, которая не сохранялась | конспект в своей таблице, с поиском, чтением, закреплением и бэкапом |
| Один пересказ | 7 секций: суть, мысли, решения, вопросы, шаги, люди, цифры, тон |
| Нельзя поправить разбор | 4 чипа режима; поправка пересобирает разбор, а не ярлык |
| Конспект — мёртвый текст | пункт «что дальше» превращается в задачу одним тапом |
| Голос — единственный вход | «Поделиться текстом» и «Выделить → Duro» идут тем же конвейером |

## 5. Карта кода

```
core/analysis/IntentRouter.kt     определение режима (чистая функция, без сети)
core/analysis/DigestBuilder.kt    сборка конспекта из транскрипта
core/analysis/ActionTitle.kt      общий чистильщик названия задачи
core/text/RussianPlural.kt        «1 выжимка / 3 выжимки / 5 выжимок»
domain/model/CaptureDigest.kt     IntentMode, CaptureDigest, DigestRecord
data/remote/OfflineVoiceParser.kt маршрутизация по режиму + forcedMode
data/repository/DigestRepository  хранение конспектов
data/local/entity/ExtraEntities   таблица digests (БД v7)
presentation/voice/ReviewBottomSheet   бейдж режима, чипы, предпросмотр
presentation/digests/DigestsScreen    список и читалка конспектов
```

## 6. Что проверено

* 252 unit-теста, все зелёные; 12 новых классов закрывают каждую найденную регрессию.
* 3 инструментальных теста, включая миграцию БД 6→7 на реальном SQLite эмулятора.
* `lintDebug` — в изменённых файлах нет ни одного замечания.
* Эмулятор `muse_visual` (Android 14, 1080×2400): все четыре режима, переопределение
  режима, создание задачи из конспекта, закрепление, удаление, пустое состояние,
